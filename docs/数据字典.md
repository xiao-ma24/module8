# 数据字典 — 学校物资管理大系统

> 库名：`material_mgmt` · MySQL 8.0 · 字符集 utf8mb4
> 本字典是 5 个子系统共同的数据契约，**表结构变更必须先更新本文件再改代码**。

## 1. 全局命名规范

- 表名、字段名统一小写下划线；每张表必须有表注释
- 主键统一为 `<实体>_id BIGINT AUTO_INCREMENT`（如 `user_id`、`material_id`、`pr_id`）；仅库存、关联表使用联合主键（如 `stock(material_id, warehouse_id, batch_no)`）
- 单据编号统一 `*_no VARCHAR(32)` 并加唯一索引，格式建议：`单据类型前缀 + yyyyMMdd + 4位流水`（如 `RK202601010001`）
- 审计字段（所有业务表必备）：`created_by`, `created_at`, `updated_by`, `updated_at`, `del_flag`(0/1 逻辑删除)
- 金额 `DECIMAL(12,2)`，数量 `DECIMAL(12,3)`，状态 `TINYINT`
- 人员字段统一 `BIGINT`，关联 `sys_user.user_id`（如 `applicant_id`、`approver_id`、`keeper_id`）；展示用冗余 `user_name`/`dept_name` 可另存
  - 工号/学号是字符串，存 `sys_user.user_no VARCHAR(32)`，**不再用 varchar 作为人员外键**
  - 教师/学生详情来自**师资系统/学生系统**，本系统只存主键与少量冗余展示字段
  - 用户主档、部门、角色、权限、字典、参数由**子系统⓪ 平台管理端**统一维护，其他子系统只读
- 分类类字段（物资分类、状态枚举等）统一由平台管理端 `sys_dict_type` / `sys_dict_item` 维护，业务表只存字典编码（如 `material.category_code`），**禁止另建 `material_category` 等平行分类表**

## 2. 共享核心表（目录与仓库由①维护，库存与流水由②统一写入）

- `material`、`supplier`、`warehouse` 由子系统①（基础数据与审批）维护，其他子系统只读
- `stock`、`stock_flow` 的**唯一写入口是子系统② 的 `InventoryService`**（合格入库、预占/释放、领用出库、借出、归还、报损核销、盘盈、盘亏九类动作，含幂等控制），③④⑤ 一律调用②的库存服务，**禁止任何模块直连改表**；①只提供目录与库存查询

## 3. 各子系统数据表

### 3.1 子系统① 基础数据与审批（韦森聍）

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `material` | 物资目录（一级数据） | material_code(唯一), material_name, category_code(→sys_dict_item), material_type(1低值易耗品/2低值耐用品), unit, ref_price, is_controlled, service_life_years(限用年限，耐用品必填), shelf_life_days(保质期天数), safe_stock |
| `warehouse` | 仓库/库房 | warehouse_name(唯一), warehouse_type(1实体仓库/2虚拟个人保管仓), location, keeper_id(→sys_user) |
| `stock` | 库存（共享核心表，按批次） | 联合主键(material_id, warehouse_id, batch_no), holder_id(个人保管人), expire_date, inbound_date, qty_on_hand(在库总量，含在借与预占), qty_available(公共可领量，个人仓恒为 0), qty_locked(预占量)；约束：三者非负且 `qty_available + qty_locked <= qty_on_hand` |

**库存数量规则（各子系统统一口径，q 为本次处理数量，均指公共库存）**

| 业务动作 | `qty_on_hand` | `qty_available` | `qty_locked` |
|---|---:|---:|---:|
| 合格采购入库 | ＋q | ＋q | 不变 |
| 审批通过并预占 | 不变 | －q | ＋q |
| 取消、关闭并释放预占 | 不变 | ＋q | －q |
| 领用出库，消耗已有预占 | －q | 不变 | －q |
| 借出，消耗已有预占 | 不变 | 不变 | －q |
| 借出，未提前预占 | 不变 | －q | 不变 |
| 完好归还 | 不变 | ＋q | 不变 |
| 已借出物资报损核销 | －q | 不变 | 不变 |
| 库内可用物资报废核销 | －q | －q | 不变 |
| 科研经费自购进入个人仓 | ＋q | 保持 0 | 保持 0 |

- 库存写入统一走 `InventoryService`（子系统②提供），其他模块不得直接更新 `stock`。
- 借出消耗预占时可用量已在审批阶段扣减，出库不得再减一次；盘盈盘亏按差异涉及可用、预占或在借物资分别处理。
- 余额更新必须带数量前置条件并在事务内校验更新行数，同时满足 `qty_available + qty_locked <= qty_on_hand`。
- `stock_flow` 以 `(biz_type, biz_id, biz_item_id)` 唯一标识一次业务操作，整单多明细、分批出库、分次归还分别去重。
- `stock_flow.change_qty` 需结合 `biz_type` 解释：借用、归还的流水不计入在库总量增减汇总；预占与释放预占不写流水，由单据状态驱动。

> 物资分类不再单独建表：统一由平台管理端 `sys_dict_type=material_category` 下的 `sys_dict_item` 维护，`material.category_code` 存字典编码。

### 3.2 子系统② 采购验收与入库（李思滢）

业务链路：**采购计划 → 采购申请 → 采购订单 → 到货验收单 → 合格入库单 → 库存/库存流水 → 入库成本接口**。字段以 `docs/sql/schema-02.sql` 与 `docs/sql/incremental/` 为准。

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `supplier` | 供应商 | supplier_id, supplier_name, contact_person, contact_phone, address, tax_no, star_level, supplier_status(1合作中/0停用) |
| `purchase_request` | 采购申请 | pr_id, pr_no(唯一), source_type, source_id, purchase_mode(1集中采购/2科研自购), holder_id(自购保管人), reimburse_voucher_no(报销凭证号), applicant_id(→sys_user), dept_id, usage_purpose, budget_no(→财务预算科目), expect_date, total_amount, priority, pr_status(0草稿/1待审/2已审/3驳回/4已转订单) |
| `purchase_request_item` | 采购申请明细 | pri_id, pr_id, material_id, qty_apply(申请数量), ref_price(参考单价), amount, qty_confirmed(核定数量) |
| `purchase_order` | 采购订单（报告表2-10，兼容多明细） | po_id, po_no(唯一，PO+yyyyMMdd+4位；历史 CD 号保留), plan_id(→purchase_plan), pr_id(→purchase_request), supplier_id, material_id(单物资口径，多明细订单取首行), po_qty(下单数量合计), unit_price(多明细取加权均价), amount(订单金额), po_date(下单日期), buyer_id(采购员→sys_user), accept_qty(累计验收数量，验收时回写), order_date, expect_date, contact_person, contact_phone, total_amount, pay_type, invoice_type, po_status(0待确认/1已确认/2部分到货/3已完成/4已取消) |
| `purchase_order_item` | 采购订单明细 | poi_id, po_id, plan_id(→purchase_plan，一明细一计划), material_id, order_qty, unit_price, amount, arrived_qty(到货数量), inbound_qty(入库数量) |
| `acceptance_order` | 到货验收单 | acpt_id, acpt_no(唯一), po_id, acpt_date, inspector_id(验收人→sys_user), deliverer(送货人), photo_urls, acpt_score, acpt_status(0待验收/1验收中/2已完成/3质量异议), quality_report, remark |
| `acceptance_item` | 验收明细 | ai_id, acpt_id, poi_id, material_id, check_qty(验收数量), pass_qty(合格数量), fail_qty(不合格数量), fail_reason, handle_type(1入库/2退货/3换货), handle_status(0待处理/1已完成), handled_at, handled_by |
| `inbound_order` | 入库单 | in_id, in_no(唯一), acpt_id, po_id, purchase_mode(1集中采购/2科研自购), holder_id(自购保管人), warehouse_id, keeper_id(入库人→sys_user), in_date, total_amount, voucher_no(→财务应付凭证号), in_status, remark |
| `inbound_item` | 入库明细（批次） | ii_id, in_id, material_id, batch_no, produce_date, expire_date, in_qty, unit_price, amount, qr_code |
| `material_inbound_interface` | 物资入库成本接口表（报告表2-11，供第5组成本结转只读） | 联合主键(in_no, material_id); in_price(入库单价，DECIMAL(10,2), ≥0), in_qty(本次入库数量，>0), in_amount(入库金额=单价×数量), in_date(验收合格并登记入库的日期), warehouse_id(→warehouse) |
| `purchase_plan` | 采购计划（报告表2-9，一计划一物资；常规补货与科研经费自购登记共用） | plan_id, plan_no(唯一，CG+yyyyMMdd+4位), plan_type(1常规补货/2临时采购), purchase_mode(1集中采购入公共库存/2科研经费自购登记入个人保管库存), dept_id(→dept), holder_id(自购实际保管人，集中采购为空), reimburse_voucher_no(报销凭证号，唯一、可空), material_id, plan_qty(>0), stock_qty(生成计划时的可用量), supplier_id(建议供应商，可空), expect_date, plan_status(0草稿/1待审批/2已批准/3已下单/4已关闭), approve_id(→approve_record) |
| `approve_record` | 统一审批记录（报告表2-12，跨模块共享控制数据） | record_id, biz_type(1领用/2借用/3报损/4采购/5报废), biz_id(被审批单据主键), approver_id(→sys_user), approve_result(0驳回/1通过), approve_time |
| `asset_inbound` | 资产入库登记表（报告字典，第8组） | rk_no(主键), in_no(唯一), appr_no(唯一), flow_no(唯一), emp_id, appr_id, store_id, asset_id(唯一), asset_name, model, qty, price, amount, invoice_no(唯一), approve_result(1通过/0驳回), in_qty, stock_qty, change_type(1入库/2出库), change_qty |

> **科研经费自购**：`purchase_mode` + `holder_id` 落在 `purchase_request`、`purchase_plan` 与 `inbound_order` 三张表；验收单通过「验收单 → 采购订单 → 采购申请」关联追溯自购方式与保管人，不重复存字段。
> **验收结论**：`acpt_status` 只表示单据流转（0待验收/1验收中/2已完成/3质量异议）；合格、不合格、部分合格由 `acceptance_item.pass_qty / fail_qty / handle_type` 逐条记录，更细且可追溯。
> **科研经费自购登记入库（报告表2-9、表2-18）**：登记申请落 `purchase_plan`（`purchase_mode=2`、`holder_id`、`plan_type` 按来源取 1 常规补货/2 临时采购），审批结论落 `approve_record`（`biz_type=4`），入库同时更新 `stock`（个人保管仓，`holder_id` 必填、`qty_available` 恒为 0）与 `stock_flow`（`biz_type=1`，`change_qty` 为正），验收合格后把生成的凭证号回写 `reimburse_voucher_no`（`purchase_request` 与 `purchase_plan` 同口径）。
> **入库成本接口（报告表2-11）**：确认入库时与 `stock`、`stock_flow` 同一事务写入 `material_inbound_interface`，一行对应「入库单 + 物资」；`in_price` 取采购订单实际下单价，`in_amount = in_price × in_qty`（四舍五入两位小数）。该表只作为第5组财务成本结转的只读依据，不参与库存数量计算；查询接口 `GET /api/v1/purchase/finance/recon`。
> **采购计划与订单（报告表2-10）**：保留「采购申请 + 多明细订单」既有结构，转订单时为每条申请明细生成一条 `purchase_plan`（`plan_status=3 已下单`、`plan_no=CG+yyyyMMdd+4位`），订单明细回填 `purchase_order_item.plan_id`，订单头回填 `plan_id/material_id/po_qty/unit_price/amount/po_date/buyer_id`（单物资订单直接取该物资；多物资订单取首行物资、数量与金额汇总、单价取加权均价）。`accept_qty` 在验收完成时按订单明细累计 `arrived_qty` 回写。

> **报告字典与本仓库的关系**：报告表2-2~表2-21 定义了 20 张核心表（`sys_user`、`dept`、`material_dept_quota`、`sys_role`、`sys_user_role`、`material`、`supplier`、`purchase_plan`、`purchase_order`、`asset_inbound`、`material_inbound_interface`、`warehouse`、`stock`、`stock_flow`、`approve_record`、`req_order`、`out_order`、`borrow_return`、`loss_order`、`sys_operation_log`）。本仓库是它的**实现超集**：为实现平台管理端与各子系统闭环，另建 `sys_menu`、`sys_role_menu`、`sys_dict_type`、`sys_dict_item`、`sys_config`、`sys_login_log`、`budget`、`purchase_request(_item)`、`purchase_order_item`、`acceptance_order/_item`、`inbound_order/_item`、`borrow_return_item`、`stocktake_order/_item`、`warning_rule`。报告表2-4 `material_dept_quota` 已按报告独立建表，与 `dept.annual_quota`（年度额度）并存：月度额度由平台管理端「部门月度额度」页面按年月核定，年度额度继续供各子系统做总量控制。报告中已列的表字段以 `docs/sql/` 为准，禁止改名或另建平行表。

### 3.4 子系统④ 借用归还报损（刘志豪）

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `borrow_return` | 借用归还（一单一物资） | borrow_no(唯一), borrower_id, material_id, warehouse_id(借出仓库), batch_no(实际出库批次), borrow_qty, returned_qty(累计完好归还), written_off_qty(累计报损核销), due_date, return_time, condition_code(1完好~4缺失), borrow_status(0待审批~5已核销)；约束：`returned_qty + written_off_qty <= borrow_qty` |
| `borrow_return_item` | 借用分次归还明细 | item_no(唯一), borrow_id, return_qty, accept_result(1完好入库/2损坏核销/3缺失核销), warehouse_id, batch_no, keeper_id(经办人→sys_user), return_time |
| `loss_order` | 报损单 | loss_no(唯一), source_type(1借用报损/2盘亏报损/3到期或超限报废), source_id, material_id, warehouse_id(来源仓库), holder_id(个人仓必填), batch_no(过期报废必填), loss_qty, reason, approve_status(0待审批/1通过/2驳回), dispose_result(1赔偿/2免赔/3报废核销), executed(0未执行/1已执行), exec_time, exec_operator_id；核销以 `executed=0` 为条件更新，防止重复扣减 |

### 3.5 子系统⑤ 盘点预警补货（金日勋）

## 4. 外部系统数据引用（重点）

### 4.1 引用原则

1. 本系统**只保存外部实体主键 + 少量冗余展示字段**（如姓名、部门名），不复制全量数据
2. 冗余字段仅作列表展示兜底，详情页优先实时调用外部系统接口
3. 涉及外部系统的字段在实体类中集中放在 `ExternalRef` 字段组，便于合并大系统时统一替换为真实接口调用

### 4.2 师资系统（教师 / 部门）

| 引用字段 | 类型 | 说明 |
|---|---|---|
| `user_id`（教师主键） | BIGINT | 领用/借用申请人、审批人、验收人、仓库保管人，关联 `sys_user.user_id` |
| `user_no`（工号，冗余） | VARCHAR(32) | 师资系统教师工号 |
| `user_name`（冗余） | VARCHAR(64) | 教师姓名 |
| `dept_id` / `dept_name`（冗余） | BIGINT / VARCHAR(128) | 教师所属部门，用于按部门统计领用 |

对接方式：`GET {师资系统}/api/teachers/{id}`；课程环境无真实系统时查模拟表 `sys_teacher`。

### 4.3 学生系统

| 引用字段 | 类型 | 说明 |
|---|---|---|
| `user_id`（学生主键） | BIGINT | 借用人为学生时的身份标识，关联 `sys_user.user_id` |
| `user_no`（学号，冗余） | VARCHAR(32) | 学生系统学号 |

| `class_name`（冗余） | VARCHAR(64) | 班级 |

对接方式：`GET {学生系统}/api/students/{id}`；模拟表 `sys_student`。

### 4.4 财务系统

字段口径与代码保持一致，采购侧只使用两个字段：

| 引用字段 | 所在表 | 类型 | 说明 |
|---|---|---|---|
| `budget_no`（预算科目号） | `purchase_request` | VARCHAR(32) | 采购申请时校验预算额度，对应财务系统预算科目 |
| `voucher_no`（应付/报销凭证号） | `inbound_order` | VARCHAR(32) | 入库完成后推送应付信息，回填财务凭证号 |
| `reimburse_voucher_no`（报销凭证号） | `purchase_request` / `purchase_plan` | VARCHAR(32) | 科研经费自购的报销凭证，唯一 |
| `in_price` / `in_amount`（实际入库单价与金额） | `material_inbound_interface` | DECIMAL(10,2) / DECIMAL(12,2) | 第5组按实际入库单价做成本结转的只读依据 |
| `compensate_amount`（赔偿金额） | 报损单推送 | DECIMAL(12,2) | 报损赔偿信息推送财务系统入账 |

对接方式：入库完成 `POST {财务系统}/api/vouchers/payable`；课程环境用模拟表 `sys_budget_subject` 只提供预算科目资料，**不作为采购程序实际读取的主表**。

### 4.5 外部系统模拟表（课程联调用，真实环境删除并以接口代替）

```sql
sys_teacher(id, teacher_no, teacher_name, dept_code, dept_name, phone)
sys_student(id, student_no, student_name, class_name, major)
sys_budget_subject(id, subject_no, subject_name, balance DECIMAL(12,2))
```

> `sys_teacher.dept_code` 是师资系统部门编码（字符串），与主系统 `dept.dept_id`（BIGINT）不同；对接时需按 `dept.dept_code` 映射。

## 6. 大系统用户信息字段说明

大系统所有子系统的"人"都落在同一张 `sys_user` 表上，避免每个子系统各建一套账号。字段按用途分五类，**共 15 个**，其中标 ★ 为必填。

### 6.1 身份标识（谁）

| 字段 | 类型 | 必填 | 说明 | 维护方 |
|---|---|---|---|---|
| `user_id` | BIGINT | ★ | 主键，系统内部使用，不对外展示 | 系统生成 |
| `user_no` | VARCHAR(32) | ★ | 工号/学号，全平台唯一，登录账号 | 管理员端 |
| `user_name` | VARCHAR(64) | ★ | 真实姓名 | 管理员端（可同步师资系统） |
| `user_type` | TINYINT | ★ | 1教职工 2学生 3外部人员（供应商联系人等） | 管理员端 |

### 6.2 组织归属（在哪个部门）

| 字段 | 类型 | 必填 | 说明 | 维护方 |
|---|---|---|---|---|
| `dept_id` | BIGINT | ★ | 所属部门，关联 `dept`；学生填所在院系 | 管理员端 |
| `title` | VARCHAR(30) | | 职称/身份：教授、讲师、实验员、本科生等，用于单据打印 | 管理员端 |

### 6.3 角色与权限（能做什么）

| 字段 | 类型 | 必填 | 说明 | 维护方 |
|---|---|---|---|---|
| `role_code` | VARCHAR(32) | ★ | 主角色编码，决定可进入哪些菜单；多角色另存 `sys_user_role` | 管理员端 |
| （权限） | — | — | 菜单级权限由 `sys_role_menu` 决定，按钮级由 `sys_menu.menu_type=3` 决定 | 管理员端 |

### 6.4 联系方式与人事（怎么联系、什么时候来的）

| 字段 | 类型 | 必填 | 说明 | 维护方 |
|---|---|---|---|---|
| `phone` | VARCHAR(20) | ★ | 手机号，用于消息通知、紧急联系 | 管理员端 / 本人 |
| `email` | VARCHAR(80) | | 邮箱，用于发送单据与审批提醒 | 管理员端 / 本人 |
| `hire_date` | DATE | | 入职/入学日期，用于统计在岗与届别 | 管理员端 |

### 6.5 账号安全与状态（能不能用）

| 字段 | 类型 | 必填 | 说明 | 维护方 |
|---|---|---|---|---|
| `password` | VARCHAR(64) | ★ | 密码 SHA-256 摘要，初始 123456，不存明文 | 系统 / 本人修改 |
| `status` | TINYINT | ★ | 1启用 0停用，停用后无法登录但历史单据保留 | 管理员端 |
| `last_login_at` | DATETIME | | 最近登录时间，用于识别长期未登录账号 | 系统自动 |
| `del_flag` | TINYINT | ★ | 0正常 1已删除（逻辑删除，不物理删） | 系统 |
| `remark` | VARCHAR(200) | | 备注，如"外聘""实习""临时账号有效期" | 管理员端 |

### 6.6 哪些字段不该由本系统管

| 信息 | 归属系统 | 本系统如何处理 |
|---|---|---|
| 身份证号、家庭住址、学历、政治面貌 | 师资系统 / 学生系统 | 不落库，需要时按 `user_no` 调接口取 |
| 学生班级、专业、年级 | 学生系统 | 仅冗余 `class_name` 用于单据打印，以学生系统为准 |
| 银行卡号、工资 | 财务系统 | 本系统只存预算科目与凭证号 |
| 人脸照片、指纹 | 一卡通/门禁系统 | 不采集 |

**一句话结论**：本系统只需要"工号+姓名+类型+部门+角色+手机+密码状态"这 7 个字段就能跑通全部业务；职称、邮箱、入职日期是增强字段，用于打印与提醒；身份证、住址等敏感信息一律不存。
