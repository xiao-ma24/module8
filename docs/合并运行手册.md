# 合并运行手册（5 个子系统 → 1 个可运行大系统）

> 目标：把 5 个独立 Spring Boot 应用 + 5 个前端工程合并为**一个 8080 端口运行的大系统**，并通过端到端冒烟测试。
> 合并期预计需要全队一起联调，本手册是操作底稿。

## 0. 开发期就要遵守的前提（决定合并成败）

| 前提 | 在哪约束 |
|---|---|
| 包结构统一 `com.school.material.<module>` | 开发约束 §2 |
| 统一响应体 + 错误码区间不冲突 | 开发约束 §3 |
| 跨系统地址走配置文件 | 开发约束 §6 |
| 表结构 = 数据字典，禁止未登记字段 | 开发约束 §5 |
| 接口实现 = `docs/api/api-0X.md` 文档 | 开发约束 §4 |
| 公共类放 `common/` 子包便于替换 | 开发约束 §2 |

## 1. 合并前检查清单（每人先自查，合并日集体复核）

**后端（每个子系统）：**

- [ ] `mvn clean package` 通过，无警告级依赖冲突
- [ ] 包结构符合 `com.school.material.<module>.{controller,service,mapper,entity,dto,config,common}`
- [ ] 无 `localhost:808X` 硬编码在 Java 代码里（全部在 yml 配置）
- [ ] MyBatis Mapper XML 的 namespace/resultMap 无跨子系统同名冲突
- [ ] 定时任务 `@Scheduled` 都集中在自己的 `config/` 里，且 `@ConditionalOnProperty` 开关控制
- [ ] 错误码全部在本子系统区间内
- [ ] `application.yml` 中只有自己子系统的专属配置，公共配置（数据源、Jackson 格式）样式一致

**数据库：**

- [ ] 所有建表与增量 SQL 可在空库上按「full-schema.sql → init-data.sql → verify.sql」完整重放，建成全部表
- [ ] `init_template.sql` 只建外部系统模拟表，不再创建业务表
- [ ] 实体字段与数据字典逐表核对一致
- [ ] 模拟表 `sys_*` 数据齐全（联调人员数据）

**前端（每个子系统）：**

- [ ] 路由路径有子系统前缀（如 `/purchase/...`），无 `/` 裸路径
- [ ] 接口 base 地址走环境变量/代理配置，无硬编码
- [ ] 组件命名带子系统语义，避免重名（如 `PurchaseOrderList.vue`）

## 2. 后端合并步骤（半天到一天）

### 2.1 建多模块工程

```
material-parent/                    (pom 打包，统一依赖版本管理)
├── material-common/                 统一响应 Result、分页 PageResult、错误码常量、
│                                   外部系统 Client 接口与 Mock 实现、工具类
├── material-base-data/              ① 
├── material-purchase/              ②
├── material-requisition/           ③
├── material-borrow/                 ④
├── material-stocktake/              ⑤
└── material-boot/                   唯一启动模块（端口 8080）
```

### 2.2 搬移步骤（每子系统约 30 分钟）

1. `git checkout -b merge/<module>`，把 `subsystem-XX/backend/src` 的包整体复制到对应模块
2. 删除自己的 `common/` 包，import 改为 `com.school.material.common`（IDE 批量替换）
3. 把启动类删除（只保留 material-boot 的启动类），`@SpringBootApplication(scanBasePackages = "com.school.material")`
4. `@MapperScan("com.school.material.**.mapper")` 统一扫描
5. 依赖统一进 parent 的 `dependencyManagement`，子模块只留业务依赖

### 2.3 统一配置（material-boot 的 application.yml）

```yaml
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3307/material_mgmt?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: ${DB_USER:root}
    password: ${DB_PASS:}
```

6. 跨子系统 HTTP 调用**改为本地 Service 直调**：`BaseStockClient` 的实现从 HTTP 版切到 `@Autowired` 直调①的 Service（接口不变，换实现类）

### 2.4 启动验证

- [ ] `material-boot` 启动无报错，`swagger-ui.html` 可看到 5 个子系统全部接口
- [ ] 5 个子系统各自核心页面功能走一遍

## 3. 前端合并步骤

1. 新建 `material-web/`（Vue3 + Vite），把 5 个前端工程按目录拆分搬入 `src/views/<module>/`
2. 路由合并：一级菜单按子系统分组；保留各工程已有路由前缀
3. API 层合并：`src/api/<module>/`，统一 axios 实例，baseURL 指向 8080
4. 组件重名冲突当场改名（加子系统前缀）
5. 验证：5 个子系统页面全部可打开、可操作

## 4. 数据库合并

开发期已共用 `material_mgmt` 一个库，合并时主要做校验：

```bash
# 空库全量重放（验证脚本完备性）
mysql -h 127.0.0.1 -P 3306 -u root -p -e "DROP DATABASE IF EXISTS material_mgmt;"
mysql -h 127.0.0.1 -P 3306 -u root -p < docs/sql/full-schema.sql
mysql -h 127.0.0.1 -P 3306 -u root -p material_mgmt < docs/sql/init-data.sql
mysql -h 127.0.0.1 -P 3306 -u root -p material_mgmt < docs/sql/verify.sql
```

## 5. 端到端冒烟测试（合并完成的标准）

按下面场景从 5 个子系统页面走完整链路，全部通过才算合并成功：

| # | 场景 | 涉及子系统 | 验证点 |
|---|---|---|---|
| 1 | 建物资档案 + 仓库，录期初库存 | ① | 库存数正确 |
| 2 | ⑤盘点：盘亏一件 → ①库存调整 | ⑤→① | 库存变动记录正确 |
| 3 | ⑤预警：库存低于下限 → 生成补货计划 → 确认转采购申请 | ⑤→② | ②出现新采购申请 |
| 4 | ②采购全流程：申请（预算校验）→ 订单 → 验收入库 | ②→①→财务 | 库存增加、移动平均价更新、凭证号回填 |
| 5 | ③领用：教师申请 → 审批 → 出库 | ③→①→师资 | 库存扣减、审批记录完整 |
| 6 | ④借用：学生借用 → 归还（一件损坏）→ 报损赔偿 | ④→①→学生→财务 | 借出扣减、完好归还回补、报损+赔偿推送财务 |
| 7 | ⑤预警复查：场景 3 补货入库后预警消除 | ⑤→① | 预警状态更新 |

**通过标准**：7 个场景全部通过 + 5 个子系统首页无报错 + 数据库无脏数据。

## 6. 常见合并问题速查

| 症状 | 原因 | 解决 |
|---|---|---|
| Bean 名冲突 | 两个子系统 Service 同名 | 按 module 前缀重命名实现类 |
| Mapper 扫不到 | 包路径不统一 | 统一 `com.school.material.**.mapper` |
| 字段冲突 | 未按数据字典开发 | 以数据字典为准，逐表核对修正 |
| 接口 404 | 合并后前缀没带子系统段 | 保持开发期前缀 `/api/v1/<module>/...` |
| 前端路由互相覆盖 | 裸路径 | 一律加子系统前缀 |
| 循环依赖 | 模块间互相 Service 注入 | 统一"只允许下层调①，⑤→②单向"，必要时事件解耦 |
