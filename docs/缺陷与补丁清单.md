## 1. 角色注解写成了单个字母（13 处）

**文件**：00 与 01 的以下控制器

- `admin/controller/ConfigController.java`
- `admin/controller/DictController.java`
- `admin/controller/LogController.java`
- `admin/controller/OverviewController.java`
- `admin/controller/ProfileController.java`
- `admin/controller/RoleController.java`
- `controller/MaterialCategoryController.java`
- `controller/MaterialController.java`

- `controller/WarehouseController.java`
- `purchase/controller/PurchaseController.java`
- `sys/controller/SysLogController.java`
- `sys/controller/SysRoleController.java`

**原代码**

```java
@RequireRole({"A", "D", "M", "I", "N"})
```

**问题**：把 `ADMIN` 拆成了五个字母，任何角色都无法匹配，`AUTH_ENFORCE=true` 时这些接口对管理员也返回 403。

**修改**

```java
@RequireRole({"ADMIN"})
```

## 2. 子系统① 鉴权拦截器不生效

**文件**：`subsystem-01-base-data/.../config/CorsConfig.java`

**原代码**

```java
registry.addInterceptor(identityInterceptor).addPathPatterns("/api/**");
```

**问题**：01 配置了 `server.servlet.context-path: /api/v1/basedata`，Spring 匹配拦截器时使用去掉 context-path 后的路径，`/api/**` 永远匹配不到，鉴权完全失效（不带任何身份也能读物资）。

**修改**

```java
registry.addInterceptor(identityInterceptor).addPathPatterns("/**");
```

## 3. 个人中心把工号当数字解析

**文件**：`subsystem-02-purchase-instock/.../controller/ProfileController.java`

**原代码**

```java
try {
    effectiveUserId = Long.valueOf(current.userId());
} catch (NumberFormatException ignored) {
    // 退回演示参数
}
```

**问题**：统一身份下 `userId` 是工号（`T0006`），解析失败后回退到默认用户，导致登录 A 显示 B。

**修改**：先尝试数字，失败则按工号查本库：

```java
private Long resolveUserId(String identity) {
    try { return Long.valueOf(identity); } catch (NumberFormatException ignored) { }
    return jdbcTemplate.queryForObject(
        "SELECT user_id FROM mat_sys_user WHERE person_no = ? AND del_flag = 0",
        Long.class, identity);
}
```

## 4. 领用/借用拦截器没有把工号换成数字 user_id

**文件**

- `subsystem-03-requisition-outstock/.../auth/AuthInterceptor.java`
- `subsystem-04-borrow-return-damage/.../auth/AuthInterceptor.java`
- `subsystem-00-admin/.../auth/AuthInterceptor.java`

**原代码**

```java
try { lu.setUserId(Long.valueOf(cu.userId())); } catch (NumberFormatException ignored) { }
lu.setUserNo(cu.userId());
lu.setUserName(cu.userId());
```

**问题**：`userId` 为 null、`userName` 变成工号；03/04 建单时 `applicant_id` / `borrower_id` 取 `LoginUser.userId`，为空会导致建单失败或数据缺失。

**修改**：按工号查 `mat_sys_user` 补齐：

```java
Map<String, Object> row = jdbc.queryForMap(
    "SELECT u.user_id, u.user_name, u.org_id, d.dept_name FROM mat_sys_user u "
  + "LEFT JOIN mat_dept d ON d.org_id = u.org_id "
  + "WHERE u.person_no = ? AND u.del_flag = 0 LIMIT 1", cu.userId());
lu.setUserId(((Number) row.get("user_id")).longValue());
lu.setUserName(String.valueOf(row.get("user_name")));
lu.setDeptId(String.valueOf(row.get("org_id")));
```

## 5. 发票登记身份可被请求体伪造

**文件**：`subsystem-01-base-data/.../purchase/controller/PurchaseController.java`

**问题**：`register` 直接使用请求体里的 `registrarUserId`，任何人可以填别人的工号。

**修改**：统一登录下强制取凭证身份：

```java
CurrentUser current = currentUserService.currentOrNull();
if (current != null) {
    req.setRegistrarUserId(current.userId());
}
```

## 7. 前端依赖组内登录状态

**文件**

- `subsystem-02-purchase-instock/frontend/src/router/index.js`
- `subsystem-02-purchase-instock/frontend/src/views/Dashboard.vue`

**问题**：路由守卫要求 `localStorage.mockUserId` 存在，统一登录后没有该值，直接跳组内登录页；盘点员工作台还会调用库管员专属的“近效期”接口导致 403。

**修改**

- 守卫改为每次向 `/api/v1/profile` 确认身份，成功后写入本地缓存；
- 近效期接口只在库管员角色下调用。
