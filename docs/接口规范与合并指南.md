## 2. REST 与统一响应

- 资源用复数名词 + HTTP 动词：`GET /api/v1/basedata/materials`、`POST /api/v1/purchase/orders`
- 统一响应体：

```json
{ "code": 0, "msg": "success", "data": {} }
```

`code=0` 成功；非 0 失败（40x 客户端错、50x 服务端错）。

- 分页参数：`pageNum` / `pageSize`，返回 `{ "total": 100, "list": [] }`

## 3. 跨子系统公共接口

**查询类（子系统①提供；开发期由② `BaseDataController` 兜底，合并后切到①）**

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/basedata/materials/{id}` | GET | 物资档案详情 |
| `/api/v1/basedata/materials` | GET | 物资分页查询（名称/分类过滤） |
| `/api/v1/basedata/warehouses` | GET | 仓库列表（含虚拟个人保管仓） |
| `/api/v1/basedata/stocks` | GET | 库存查询（materialId + warehouseId + batchNo） |

**库存变更（唯一写入口在子系统② `InventoryService`）**

| 动作 | 说明 | 幂等键 |
|---|---|---|
| 合格入库 IN | 验收合格后入公共仓或个人保管仓 | `(biz_type=1, biz_id, biz_item_id)` |
| 预占 / 释放 | 领用提交时锁可用量，驳回或出库时释放 | 同上 |
| 领用出库 / 借出 | 扣减可用量，出库同时扣在库量 | 同上 |
| 归还 / 报损核销 | 完好归还回库；损坏缺失转报废核销 | 同上 |
| 盘盈 / 盘亏 | 盘点差异审批后调整余额 | 同上 |

**库存变更接口（具体契约，子系统② `InventoryController` 提供，③④⑤ 调用）**

| 接口 | 方法 | 动作 | 数量口径 |
|---|---|---|---|
| `/api/v1/purchase/inventory/reserve` | POST | 审批通过并预占 | 在库不变、可用 −q、预占 +q |
| `/api/v1/purchase/inventory/release` | POST | 取消/关闭释放预占 | 在库不变、可用 +q、预占 −q |
| `/api/v1/purchase/inventory/issue` | POST | 领用出库（消耗预占） | 在库 −q、预占 −q |
| `/api/v1/purchase/inventory/issue-direct` | POST | 领用出库（未预占，一次性扣减） | 在库 −q、可用 −q |
| `/api/v1/purchase/inventory/borrow-out?reserved=false` | POST | 借出 | 在库不变、可用 −q |
| `/api/v1/purchase/inventory/return-good` | POST | 完好归还 | 在库不变、可用 +q |
| `/api/v1/purchase/inventory/write-off` | POST | 已借出物资报损核销 | 在库 −q |
| `/api/v1/purchase/inventory/scrap` | POST | 库内可用物资报废核销 | 在库 −q、可用 −q |
| `/api/v1/purchase/inventory/profit`、`/loss` | POST | 盘盈 / 盘亏（子系统⑤） | 见 `InventoryService` |
| `/api/v1/purchase/inventory/batches` | GET | 出库候选批次（先到期先出） | 只读，排除个人仓与过期批次 |

请求体统一为：

```json
{ "materialId": 1, "warehouseId": 1, "batchNo": "INIT-01-001-A",
  "qty": 8, "bizId": 1, "bizItemId": 0, "operatorId": 3 }
```

`bizId` 传调用方单据主键（出库单 / 归还明细 / 报损单），②侧以 `(biz_type, biz_id, biz_item_id)`
唯一键拦截重复入账：重复提交返回 2339 且余额不变。

跨子系统调用示例：

| 调用方向 | 场景 |
|---|---|
| ② → 财务系统 | 入库完成写入报销凭证号，回填 `finance_voucher_no` |
| ③ → ② | 提交领用时预占，审批通过后领用出库；申请时查库存余量 |
| ④ → ② | 借出/归还/报损调用②库存服务对应动作 |
| ⑤ → ② | 盘点差异调整库存；预警查询库存 |
| ⑤ → ② | 补货计划确认后生成采购计划 `purchase_plan`（`plan_type=1`），进入采购审批 |
| 全部 → ① | 物资目录、供应商、仓库查询；审批记录写入 `approve_record` |
| ④ → 财务系统 | 报损赔偿信息推送财务 |
| ③④ → 师资/学生系统 | 申请人/审批人身份校验与详情展示 |

## 4. 外部系统对接约定

- 在公共模块定义统一客户端接口（合并前各子系统各自实现）：

```java
public interface TeacherClient { TeacherDTO getTeacher(String userId); }
public interface StudentClient { StudentDTO getStudent(String userId); }
public interface FinanceClient { String pushPayable(PayableDTO dto); }
```

- 开发期使用 `MockExternalSystemClient`（查模拟表 `sys_teacher` / `sys_student` / `sys_budget_subject`）
- 联调期切换为真实 HTTP 实现（配置文件切换，不改业务代码）

## 5. 合并方案：5 个子系统 → 1 个大系统

**阶段一（现在）**：各子系统独立 Spring Boot 应用、独立前端，按上表端口运行，HTTP 互调。

**阶段二（后端合并）**：Maven 多模块：

```
material-parent (pom)
├── material-common          # 统一响应、公共实体、外部系统Client、工具类
├── material-base-data       # ①
├── material-purchase        # ②
├── material-requisition     # ③
├── material-borrow          # ④
├── material-stocktake       # ⑤
└── material-boot            # 整合启动模块，统一端口 8080，扫描全部模块
```

要点：子系统内 Controller/Service/Mapper 包结构保持一致（`com.school.material.<module>.controller` 等），合并时按模块搬移包即可；跨系统 HTTP 调用改为本地 Service 直调。

**阶段三（前端合并）**：合并为一个 Vue 3 工程，按子系统划分路由与页面模块。

**阶段四（外部联调）**：师资/学生/财务系统按真实接口对接，删除模拟表。
