# 开发约束与规范（强制遵守）

> 本规范的目的：**5 个子系统由 4 人独立开发，最后必须能无冲突合并为一个可运行的大系统**。
> 每条约束都服务于这个目标。违反规范的 PR 会被打回。

## 1. 分支与 PR 约束

- `main` 为保护分支：**禁止直接 push**，只接受 PR 合入
- 该规则有两道闸：① 仓库钩子 `.githooks/pre-push`（克隆后执行 `git config core.hooksPath .githooks` 启用）；② Gitee 服务端「保护分支规则」（仓库 → 管理 → 分支设置 → main → 禁止直接推送、合并需审核）。**两道都要开**，只有文档约定不算约束
- 个人分支命名：`feature/<子系统编号>-<姓名拼音缩写>`（01-wsn / 02-lsy / 034-lzh / 05-jrx）
- 每个功能点一个 PR，描述清楚"做了什么 + 自测结果"
- PR 合入前必须：本地编译通过（`mvn clean package`）、自测通过、相关文档已同步
- 合并 main 前先 `git pull --rebase origin main` 解决冲突

## 2. 后端工程结构约束（合并时直接按包搬移，务必统一）

每个子系统 Spring Boot 工程统一使用以下包结构：

```
com.school.material.<module>          # module: basedata / purchase / requisition / borrow / stocktake
├── controller/     # 只做参数校验和调用 service，不写业务逻辑
├── service/        # 业务逻辑，接口 + impl
├── mapper/         # MyBatis Mapper 接口（注解或 XML）
├── entity/         # 数据库表实体（与数据字典字段一一对应）
├── dto/            # 请求/响应对象（Req/Resp 后缀）
└── config/         # 本子系统配置类
```

- 启动类统一放 `com.school.material.<module>.Application`
- 公共类（统一响应、分页、工具类）开发期**各自复制一份**到 `common/` 子包（包名 `com.school.material.<module>.common`），合并期由 material-common 替换，业务代码只改 import
- 时间类型统一 `LocalDateTime`，金额 `BigDecimal`，禁止 `Date`/`double`
- 实体类使用 Lombok `@Data`

## 3. 统一响应与错误码约束

所有接口返回统一响应体（见 `docs/接口规范与合并指南.md` §2）。

**错误码区间分配**（合并时避免冲突，新错误码必须在本子系统区间内取）：

| 子系统 | 错误码区间 |
|---|---|
| ① 基础数据与审批 | 1000–1999 |
| ② 采购入库 | 2000–2999 |
| ③ 领用出库 | 3000–3999 |
| ④ 借用报损 | 4000–4999 |
| ⑤ 盘点补货 | 5000–5999 |
| 公共/参数错误 | 400、401、403、500 等标准语义码 |

## 4. 统一接口文档约束（重点）

### 4.1 文档即契约

- 每个子系统在 `docs/api/` 下维护一份接口文档：`api-01.md` ~ `api-05.md`（模板：`docs/api/api-template.md`）
- **接口先行**：编码前先写文档 → 群内确认 → 再实现；实现必须与文档一致
- 文档头部维护"变更记录"表：日期、修改人、变更内容
- **跨子系统接口**（①的库存变更、②的采购申请等，见接口规范 §3）是公共契约，修改必须全群确认

### 4.2 每个接口的文档必须包含

1. 路径 + 方法 + 功能说明
2. 请求参数表（名称、类型、必填、说明）
3. 响应示例 JSON（含成功和至少一种失败）
4. 触发的业务规则（如"库存不足返回 1xxx"）

### 4.3 建议自动文档（可选但推荐）

后端统一引入 `springdoc-openapi-starter-webmvc-ui`（Spring Boot 3）：

```xml
<dependency>
  <groupId>org.springdoc</groupId>
  <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
  <version>2.5.0</version>
</dependency>
```

启动后访问 `http://localhost:808X/swagger-ui.html`，联调时直接对照调试。注解只做辅助，**markdown 文档仍是唯一契约**。

### 4.4 联调工具

推荐全队统一用 **Apifox**（或 Postman）：每人导出自己子系统的接口集合（按 `docs/api/api-0X.md` 建），合并期导入一个大集合联调。

## 5. 数据库变更约束

- **先改 `docs/数据字典.md`，再写 SQL，再改代码**，三步必须在同一个 PR 内
- 增量脚本放在 `docs/sql/incremental/`，命名 `V<日期>_<子系统编号>_<说明>.sql`（如 `V20261109_02_add_supplier_credit.sql`）
- **禁止修改已合入 main 的历史脚本**，只能新增增量脚本
- 字段命名遵循数据字典全局规范（§1）；跨子系统共享字段（user_id、source_no 等）禁止私自重命名
- 库存表 `stock` / `stock_flow` 只能由子系统② 的 `InventoryService` 写，**其他子系统（含①）一律调用②的库存服务**，禁止直连改表；库存余额与流水必须在同一事务内更新

## 6. 跨子系统调用约束

- 调用方在 `application.yml` 中配置被调方地址，**禁止硬编码 IP/端口**：

```yaml
material:
  base-service-url: http://localhost:8081   # 子系统①地址
  purchase-service-url: http://localhost:8082
```

- 统一超时：连接 3s、读取 5s；失败要有明确错误码返回，不许静默吞异常
- 库存变更服务（②提供）**幂等**：同一 `source_no` 重复请求返回成功不重复执行
- 单据号格式统一（数据字典 §1），保证全系统唯一

## 7. 外部系统（师资/学生/财务）约束

- 按接口规范 §4 定义 Client 接口（`TeacherClient` / `StudentClient` / `FinanceClient`），开发期实现 `MockXxxClient` 查模拟表 `sys_*`
- **业务代码只依赖 Client 接口**，用 `@Profile` 或配置开关切换 Mock/真实实现，联调期不改业务代码
- 模拟表字段见数据字典 §4.5，禁止各子系统私建不同的模拟表结构

## 8. 接口完成标准（Definition of Done）

一个接口能进入 main 必须满足：

- [ ] 文档（`docs/api/api-0X.md`）已更新且与实现一致
- [ ] 统一响应格式、错误码在本子系统区间内
- [ ] 请求参数做了非空/格式校验
- [ ] `mvn clean package` 编译通过
- [ ] Apifox/Postman 自测通过（成功 + 至少一种失败场景）
- [ ] 涉及表结构变更的，数据字典 + 增量 SQL 已同步
- [ ] 跨子系统调用方同步过契约（群消息截图放 PR 描述）
