# 统一登录集成说明

## 1. 总体结构

```
浏览器
  │  Cookie: CAMPUS_SESSION（HttpOnly，登录时由认证服务写入）
  ▼
Nginx（同域名）
  ├─ 静态前端：6 份站点，均部署在根路径
  └─ /api/v1/**  → auth_request 核验 → 注入身份头 → 按路径转发到 8080~8085
```

认证与授权分工：

| 事项 | 负责方 | 依据 |
| --- | --- | --- |
| 你是谁 | DBA 认证服务 | 登录时核验，网关下发 `X-DBA-USER-ID` |
| 什么角色 | DBA 账号配置 | 网关下发 `X-DBA-ROLE` |
| 哪个部门 / 仓库 | 各模块自己 | 用工号查 `mat_sys_user.org_id` |
| 能看哪些数据 | 各模块自己 | 角色 + 部门 + SQL 条件 |

## 2. 认证服务接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/auth/login` | 登录，写入 `CAMPUS_SESSION` |
| POST | `/api/auth/logout` | 退出 |
| GET | `/api/auth/me` | 当前用户 |
| POST | `/api/auth/internal/verify` | 组内后端核验（body 传 token） |
| GET | `/api/auth/internal/verify` | Nginx `auth_request` 用（header 传 token，响应头返回身份） |

GET 核验请求：

```http
GET /api/auth/internal/verify
X-Internal-Secret: <内部密钥>
X-Session-Token: <CAMPUS_SESSION 的值>
```

成功响应（同时写响应头，供 `proxy_set_header` 使用）：

```http
HTTP/1.1 200
X-User-Id: T0006
X-User-Role: APPLICANT
X-User-Business: 000002
```

失败返回 401，网关原样透传给浏览器。

## 3. Nginx 路径分发

| 路径前缀 | 后端 |
| --- | --- |
| `/api/v1/admin/` | 8080 |
| `/api/v1/basedata/` | 8081 |
| `/api/v1/base/`、`/api/v1/purchase/`、`/api/v1/profile` | 8082 |
| `/api/v1/requisition/` | 8083 |
| `/api/v1/borrow/` | 8084 |
| `/api/v1/stocktake/` | 8085 |

完整配置见 `deploy/nginx.conf` 与 `deploy/api-proxy.conf`。

## 4. 模块侧取身份

唯一入口是各模块的 `CurrentUserService`：

```java
CurrentUser me = currentUserService.current();   // 未登录抛 401
// me.userId()     工号
// me.role()       角色
// me.businessId() 部门（按工号查库得到，不是请求头）
```

`CurrentUserServiceImpl` 的实现顺序：

1. 读 `X-DBA-USER-ID`；
2. 读 `X-DBA-ROLE`；
3. 用 `X-DBA-USER-ID` 查 `mat_sys_user`，取 `org_id`；
4. `X-DBA-BUSINESS-ID` 仅在查库失败时回退（过渡期兼容，可关闭）。

## 5. 角色映射

各模块角色编码与账号一一对应，一个账号一个角色：

| 账号 | 角色 | 可进入的模块功能 |
| --- | --- | --- |
| `T0005` | ADMIN | 全部 |
| `T0002` | PURCHASER | 采购申请、订单、验收、供应商、报表、物资目录 |
| `T0007` | CHECKER | 到货验收、应收货订单、物资目录 |
| `T0003` | STORE_KEEPER | 入库、仓库、领用审批/出库、借用审批/借出/归还、预警 |
| `T0004` | STOCKTAKER | 盘点任务、补货计划、预警、物资目录 |
| `T0006` | APPLICANT | 采购申请、领用申请、借用申请、归还、发票登记 |
| `T0001` | DEPT_HEAD | 采购申请与审批、领用申请、借用申请、发票登记 |

同一人在不同模块需要不同角色时，**开两个账号**，不要复用。

## 6. 与组内演示登录的关系

- `AUTH_ENFORCE=false`：走组内 `X-Token` / `handoff` 登录，方便课程演示；
- `AUTH_ENFORCE=true`：只认统一身份，未登录 401、越权 403。

两套互不影响，切换只改环境变量。

## 7. 部署注意

1. Cookie 按主机名共享，6 个前端必须和认证服务**同域名**（端口可不同）；
2. 前端使用绝对路径 `/assets/`，必须部署在站点根路径；
3. `X-Internal-Secret` 不要写进前端，只放在 Nginx 与认证服务配置中；
4. 后端 8080~8085 只监听内网，不要直接暴露公网。
