### 4.5 Nginx 示例（推荐：每份前端一个站点，同域名不同端口）

**方案 A（推荐，产物可直接用，无需重新构建）**

把各前端产物部署为 6 个静态站点，共用一份 API 反代配置。

`/etc/nginx/conf.d/material-api.conf`：

```nginx
# 被各站点 include，负责把 /api/v1/** 分发到 6 个后端
location /api/v1/auth/        { proxy_pass http://127.0.0.1:8080; include /etc/nginx/proxy_common.conf; }
location /api/v1/admin/       { proxy_pass http://127.0.0.1:8080; include /etc/nginx/proxy_common.conf; }
location /api/v1/basedata/    { proxy_pass http://127.0.0.1:8081; include /etc/nginx/proxy_common.conf; }
location /api/v1/requisition/ { proxy_pass http://127.0.0.1:8083; include /etc/nginx/proxy_common.conf; }
location /api/v1/borrow/      { proxy_pass http://127.0.0.1:8084; include /etc/nginx/proxy_common.conf; }
location /api/v1/stocktake/   { proxy_pass http://127.0.0.1:8085; include /etc/nginx/proxy_common.conf; }
location /api/v1/base/        { proxy_pass http://127.0.0.1:8082; include /etc/nginx/proxy_common.conf; }
location /api/v1/purchase/    { proxy_pass http://127.0.0.1:8082; include /etc/nginx/proxy_common.conf; }
location /api/v1/profile     { proxy_pass http://127.0.0.1:8082; include /etc/nginx/proxy_common.conf; }
```

各站点示例（其余 5 个同样写法，只改 `listen` 与 `root`）：

```nginx
server {
    listen 5182;
    server_name _;
    root /opt/school-material/dist/frontend;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    include /etc/nginx/conf.d/material-api.conf;
}

server {
    listen 5183;
    server_name _;
    root /opt/school-material/dist/frontend-m03;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    include /etc/nginx/conf.d/material-api.conf;
}
# 5173 → frontend-m01、5180 → frontend-m00、5184 → frontend-m04、5185 → frontend-m05
```

`/etc/nginx/proxy_common.conf`：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 60s;
client_max_body_size 20m;
```

> 6 个站点与后端在同一 host，Cookie 天然共享，无需额外 CORS 放行——**但 `.env` 的 `CORS_ALLOWED_ORIGINS` 仍必须包含这 6 个站点的完整来源**（`https://<host>:5173` … `:5185`），否则浏览器 POST 自带的 `Origin` 会被后端判定为非法跨域（403 `Invalid CORS request`）。
> 生产上建议统一套 HTTPS（各端口同样配置证书）。
> DBA 统一门户的模块入口分别指向 `http(s)://<host>:5173/`、`:5180/`、`:5182/`、`:5183/`、`:5184/`、`:5185/`。

**方案 C（没有 Nginx，用内置静态服务直接跑产物；适合新电脑快速验证/临时演示）**

```bash
node scripts/serve-frontends.mjs
# 01 → http://localhost:5173/   00 → :5180   02 → :5182   03 → :5183   04 → :5184   05 → :5185
# 端口被占用时可整体偏移：FE_PORT_OFFSET=1000 node scripts/serve-frontends.mjs
# 后端不在本机时：API_HOST=<host> node scripts/serve-frontends.mjs
```

该脚本对每个站点做了 SPA 回退（`/base/material` 这类深链不会 404），并把 `/api/v1/**` 按前缀反代到 8080~8085，等价于方案 A 的 Nginx 配置，仅需 Node 18+。

**站点打不开（404）排查**

1. 确认该端口有进程：`lsof -i:5173`；没有进程说明前端站点没启动（`start-all.sh` 只启动后端）。
2. 用 Nginx 时确认 `root` 指向 `dist/frontend-m0X`，且 `location / { try_files $uri $uri/ /index.html; }` 存在，否则深链会 404。
3. 直接访问根路径 `/` 也 404 时，多半是 `root` 写错（指到了 `dist` 而不是具体站点目录）。

**方案 B（同域名子路径 `/m03/` 这种）**

需要把各前端 `vite.config.js` 的 `base` 改为 `/m0X/` 并重新构建，同时前端路由需使用 `import.meta.env.BASE_URL`。当前产物按「独立站点」构建，未适配子路径，若 DBA 要求单域名子路径部署，请提前告知，我们重新出一版产物。

## 集成模式切换（AUTH_ENFORCE）

| 取值 | 行为 | 使用场景 |
|---|---|---|
| `false`（默认） | 使用本组自建登录页，`X-Token` 鉴权 | 课程演示、页面截图 |
| `true` | 只认 DBA 下发的 `X-DBA-USER-ID` / `X-DBA-ROLE`；无身份返回 **401**，角色不符返回 **403** | DBA 统一登录联调/上线 |

切换只需改环境变量并重启，不需要重新打包：

```bash
AUTH_ENFORCE=true
```

集成模式下前端不再作为入口（与《接入通知》第五节一致：正式对外只保留统一入口）。
各接口的角色要求由 `@RequireRole` 注解声明，取值见《身份权限矩阵》。
