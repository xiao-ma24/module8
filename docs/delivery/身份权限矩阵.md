# 身份权限矩阵（DBA 角色映射基线）

> `CurrentUser.roleCode` 的合法取值如下。DBA 认证中心需把自有角色映射到这些编码（多角色时取主角色）。
> 数据范围用于服务端过滤：`全校` = 不限制；`部门` = 按 `businessId` 或用户所属部门；`本人` = `userId`。

## 1. 角色定义

| 编码 | 名称 | 数据范围 | 职责 |
| --- | --- | --- | --- |
| `ADMIN` | 系统管理员 | 全校 | 用户、角色、部门、字典、参数、审计日志、平台总览 |
| `DEPT_HEAD` | 部门负责人 | 部门 | 本部门采购/领用/借用审批 |
| `PURCHASER` | 采购员 | 全校 | 采购申请受理、订单、验收跟踪、财务核对、补货计划 |
| `STORE_KEEPER` | 仓库管理员（库管员） | 全校 | 到货验收、入库、领用出库、借出/归还/报损、库存查询 |
| `APPLICANT` | 教职工/申请人 | 本人 | 采购申请、领用申请、借用申请、个人中心 |
| `STUDENT` | 学生 | 本人 | 领用申请、借用申请、个人中心 |
| `CHECKER` | 验收人 | 全校 | 到货验收、数量质量核验（与库管员岗位分离） |
| `STOCKTAKER` | 盘点员 | 全校 | 盘点任务、实盘录入、差异登记、预警核实、补货建议（不含审批与调账） |

> 库管员与验收人分离、盘点员不直接调账，是内控要求；DBA 映射角色时请保持职责分离。

## 4. 数据范围落地说明

- 当前版本由各业务接口按 `userId` / 部门参数过滤；统一登录接入后，
  服务端应以 `CurrentUser` 为准，忽略前端传入的身份参数。
- `businessId` 建议：
  - `DEPT_HEAD` → 部门 ID（`mat_dept.dept_id`）
  - `STORE_KEEPER` → 仓库 ID（`mat_warehouse.warehouse_id`），未指定则全校仓库
  - 其他角色可为空
- P1 将增加统一鉴权拦截器，按本矩阵做接口级 403 校验。
